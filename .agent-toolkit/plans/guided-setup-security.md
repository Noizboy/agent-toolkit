# Guided runtime and MCP setup: preventive security review

Date: 2026-10-05. Role: Security-Agent. Status: implementation may proceed within the controls below; closure requires QA evidence. This is a preventive review, not a scan, pentest or compliance claim.

## Scope and evidence

The user requested guided setup during toolkit installation for optional Strix, Specify, ClawScan, Lighthouse and Graphify runtimes, Strix authentication, selected-project MCP credentials and connection checks. Assets are project files and configuration, user credentials, installed executables and local machine resources. Trust boundaries are the bundled installer versus downloaded metadata/artifacts, package managers versus package code, user input versus subprocess arguments, and toolkit configuration versus existing client customization.

Reviewed existing `installer_core.py`, `manage.py`, `configuration.py`, `sources.py` and `probe.py`. Existing safe-path validation, controlled ExportConflict reporting, native-provider ownership checks, project-isolated npm runtime, limited MCP child environment and initialize/tools-list-only probes should be retained. No application code, scan target, pentest, model inference or code upload is included.

## Minimal implementation controls

1. Maintain bundled, reviewed recipes keyed by known tool IDs. Downloaded registry data must not provide executable commands, installer scripts, arbitrary package names, executable URLs or lifecycle hooks. Accept only fixed official repositories/registries and exact resolved versions/commits. An unsupported platform or recipe stays manual with a fixed official help URL.
2. Install into project-owned isolated runtime directories or use existing commands without upgrading/replacing them. Do not globally alter PATH, install Docker, enable virtualization/WSL, change services, install system components, invoke elevation or modify a client other than the selected provider. Docker detection is a bounded readiness check and official guidance, not a system installer. Do not run `specify init` or Graphify hooks against the real project during setup.
3. Resolve and record version plus digest before installation. npm may reuse pinned integrity/dependency-lock checks and `--ignore-scripts`. Python wheels may be installed through pip into an isolated environment with exact artifact hashes and dependencies; disallow remote sdist/build-code execution in this scope. Native release archives require verified upstream SHA-256 metadata and fixed owner/repo asset names. A computed local hash alone is not publisher authenticity. If verifiable metadata or platform compatibility is missing, defer that recipe rather than silently weaken verification.
4. Bound HTTP metadata/artifact bytes, archive expanded bytes and member count, redirects and subprocess duration. Require HTTPS with normal certificate verification. Validate every redirect destination against the recipe's official host allowlist before opening it; never forward secrets through a redirect. Stage downloads before activation, verify complete digest, then atomically record completion. Corrupt or partial state must not produce an installed/ready verdict.
5. Extract archives with an explicit member allowlist. Reject absolute/drive/UNC paths, `..`, backslash variants, NUL/control characters, symbolic links, hard links, special files and duplicate/conflicting paths. Use existing `safe_path` on runtime parents, staging destinations and activation destinations, including junction/reparse points. Preflight all destinations before activation. Preserve customized runtime manifests, project files, native client files and portable locks; report a deliberate-merge conflict instead of silently overwriting.
6. Use subprocess argument arrays with `shell=False`, a fixed executable and bounded timeout. Invoke npm's JavaScript entrypoint directly on Windows. Validate model/provider identifiers and exact versions; never use user input as flags, command fragments, URLs or recipe selectors beyond allowed IDs. Pass credentials only in a narrow child environment, never command arguments. Do not execute custom MCP commands or arbitrary PATH commands automatically just because they appear configured; report existing command availability separately from trusted-managed executable verification.
7. Guided credential entry must be masked and optional. Do not log entries, stdout/stderr, tokens, raw auth status, credential URLs or exceptions containing these. Do not persist raw credentials in project JSON, inventory, lock files, reports, native configuration or source control. Session-only environment credentials are acceptable with an explicit notice that reopening the client requires external secure configuration. Prefer secure OS-backed user storage for durable secrets; an ignored plaintext project file is not an adequate replacement. A narrowly scoped Windows compatibility option may explicitly opt into a named current-user environment variable through the registry API, after disclosing that the value is plaintext and inherited by future processes. It must be off by default, never overwrite a differing existing value, never use `setx`/shell commands, never enumerate/report registry values and never claim encryption or protection from other processes running as the user. Manual-only persistent configuration remains the fallback on other platforms. This exception changes no project file or provider configuration and requires dedicated tests for declined consent, existing-value conflict and redaction.
8. ChatGPT login is owned by Strix's documented interactive auth flow. Never read/copy Codex or another client's token files, harvest a browser session, or parse/store OAuth tokens in the toolkit. Offer the installed official CLI's browser flow only on explicit user selection, with cancellation and timeout; a bundled frozen executable may need a separate visible terminal solely for that interaction. Prefer its documented bounded `auth status` check over loading a token-bearing auth file. Return only recognized status fields and discard raw output. If upstream lacks a status command, file-presence alone is at most session-file-detected, not authenticated; no token extraction is allowed. Distinguish session detected from successful model execution. API-key mode requires a validated model selection plus a provided environment credential; ChatGPT mode must not falsely require `LLM_API_KEY`.
9. Probes remain initialize and tools/list only, against selected managed endpoints/entrypoints. Credentials are isolated per MCP. Disable HTTP redirects when authenticated, validate response limits and discard untrusted returned descriptions from persisted summaries. No tool calls, scan commands, model calls, repository uploads or localhost service discovery. Unknown/custom MCPs remain unprobed with an explanation.
10. Write non-secret, timestamped results for selected/skipped, source resolved, downloaded, hash checked, installed, command detected, authenticated, prerequisites missing and protocol verified. None alone establishes scan readiness or loading in the current AI conversation. Surface Docker CLI present but daemon unavailable, missing Chrome, existing command unverified and authentication cancelled as distinct states. A failure in one optional component must not falsely fail successfully installed agents or falsely mark the entire setup ready.

## OWASP Top 10:2025 applicability

| Category | Scenario and control | Planned negative verification |
|---|---|---|
| A01 Broken Access Control | Writes escape selected project through links, archive paths or another provider. Apply safe paths, isolated ownership and no elevation. | Traversal, Windows drive/UNC names, symlink/junction parent and other-provider sentinel stay untouched. |
| A02 Security Misconfiguration | Global package/PATH or Docker changes, unwanted hooks, arbitrary MCP execution. Fixed recipes and project-local installs; manual system guidance; managed probes only. | Unselected tools/providers and custom MCP commands never execute; no init/hooks/global install. |
| A03 Software Supply Chain Failures | Compromised metadata points to another publisher or arbitrary executable. Fixed official recipes, pinned versions/commits, verified artifact digests, suppressed package scripts. | Wrong package/repo/host/version/hash rejected; no fallback to unverified source/build. |
| A04 Cryptographic Failures | Keys/tokens enter files, reports, arguments or insecure transport. HTTPS and normal TLS, narrow child env, no raw-secret persistence. | Secret fixture absent from serialized files/logs/args/errors; invalid TLS/redirect destination fails closed. |
| A05 Injection | Model/version/path becomes shell code or flags. Structured argv and validators; fixed command recipes. | Metacharacter/leading-option payload rejected or one data argument; never shell evaluation. |
| A06 Insecure Design | Installation implies pentest approval or full runtime readiness. Opt-in component selections, no active scanning/inference/upload, explicit states. | Setup/probe cannot invoke domain tool, scan target, model call, hooks or init. |
| A07 Authentication Failures | Blind OAuth-token reuse, false API requirement, leaking login output. Official interactive Strix flow; auth-mode-specific validation, no token copying. | Cancelled/expired/malformed auth output not authenticated; ChatGPT branch does not require API key or read client auth stores. |
| A08 Software or Data Integrity Failures | Corrupt archive/lock or partial install overwrites valid custom files. Hash validation, staged activation, ownership/conflict checks. | Corrupt/hash-mismatched/partial payload fails; customized files byte-preserved; no success state on interrupted activation. |
| A09 Security Logging and Alerting Failures | Generic success masks missing prerequisite; logs expose secrets. Timestamped non-secret per-component outcomes. | Failure and skipped states visible; unexpected secret-bearing exceptions sanitized; runtime/protocol statuses distinct. |
| A10 Mishandling of Exceptional Conditions | Download/decompression/subprocess hangs, excessive output, repeated retry corrupts state. Limits, cancellation, timeout/cleanup and idempotent retry. | Oversized metadata/archive/output, subprocess timeout, broken metadata and interrupted downloads stay bounded and retryable. |

All ten categories were reviewed. Web/session/database-specific mechanisms not introduced here are outside scope; this does not certify the toolkit or upstream tools against all OWASP controls.

API Top 10:2023 concerns relevant to API consumption are API4 resource bounds, API7 destination validation, API8 safe configuration, API9 accurate inventory and API10 distrust of metadata responses. API1/API3/API5 object/function authorization and API6 business-flow controls are not newly exposed service surfaces. API2 applies through managed authentication handling without implementing OAuth itself.

## Required proportional QA evidence

Use mocked HTTP/package-manager processes and synthetic archives in disposable projects for all negative cases above. Verify successful selected recipes, idempotent retry, pre-existing custom-file preservation, nonselected-provider preservation, CLI/GUI cancellation and secret redaction. Test Windows junctions even if symlink creation is unavailable. Mock a Docker CLI whose daemon is unavailable. Test existing unmanaged commands separately from managed installs. If current-user environment persistence is implemented, mock registry operations and prove no write without explicit opt-in, no overwrite of conflicting values and no raw values in subprocess args/logs/results. Confirm MCP probes emit only initialize/initialized/tools-list messages. Run the existing regression suite.

Do not perform real package installs, authentication, scans or uploads as part of this security review. Real installation of a selected runtime can be a separate authorized smoke check after preventive controls are implemented; model inference and pentesting remain separate explicit scopes.

## Verdict and residual risks

Preventive verdict: proceed with guided component selection, verified project-local runtime recipes, documented interactive Strix auth, masked session-only MCP credentials, bounded readiness checks and existing managed MCP protocol probes, subject to the controls above. The separate off-by-default, disclosed Windows current-user environment compatibility option is acceptable only under control 7. Reject automatic Docker/system provisioning, downloaded shell scripts, OAuth token copying and silent custom-file replacement.

Residual risks include upstream dependency compromise despite a matching upstream digest, user-selected trusted executables, absent platform builds, missing secure credential persistence and untested real auth/model execution. Report these concrete limitations. If a runtime requires sdist build execution, unsupported native installer or durable plaintext secrets, defer it to official manual guidance and return to Security before expanding scope.
